# نظام إدارة ماكينات الليزر/CNC

نظام كامل (Backend + Frontend + Database) لإدارة وتنظيم إنتاج ماكينتي ليزر/CNC (كبيرة وصغيرة)، مع تسجيل دخول، صلاحيات (مشرف/مشغل)، رفع ملفات حقيقي، وتحديث لحظي بين كل المستخدمين المتصلين.

---

## 1. محتويات المشروع

```
laser-system/
├── backend/              ← السيرفر (Node.js + Express + MySQL + Socket.io)
│   ├── src/
│   │   ├── config/db.js          اتصال قاعدة البيانات
│   │   ├── middleware/           المصادقة (JWT) ورفع الملفات (Multer)
│   │   ├── routes/               مسارات API (auth, users, machines, logs, notifications)
│   │   ├── utils/                دوال مساعدة + seed.js لتهيئة المستخدم الرئيسي
│   │   └── server.js             نقطة تشغيل السيرفر
│   ├── uploads/           ← الملفات المرفوعة فعلياً تُخزَّن هنا
│   ├── package.json
│   └── .env.example       ← نموذج متغيرات البيئة (انسخه إلى .env وعدّله)
│
├── frontend/              ← الواجهة (HTML + React عبر CDN، بدون أي بناء/build)
│   ├── index.html         الواجهة الكاملة
│   └── config.js          ← هنا تضع رابط السيرفر بعد النشر
│
├── database.sql           ← هيكل قاعدة البيانات الكامل + بيانات أولية (لتنصيب جديد من الصفر)
└── migration_thumbnail.sql ← شغّله فقط إذا كانت قاعدة بياناتك منشأة مسبقاً (يضيف دعم صورة المعاينة بدون حذف بياناتك)
```

## 2. ما الذي يفعله النظام؟

- **تسجيل دخول** بصلاحيتين:
  - **مشرف (Admin)**: تحكم كامل — تشغيل/إيقاف الماكينات، إضافة/حذف/إعادة ترتيب الملفات، تعديل الاسم/الوقت/الحالة، رفع/تغيير صورة المعاينة، إدارة المستخدمين.
  - **مشغّل (Operator)**: يرى كل البيانات، ويمكنه **تعديل الوقت وحالة الملف فقط** (انتظار/جاري العمل/تم القص/تم التسليم) — لا يملك صلاحية تشغيل/إيقاف الماكينة، الحذف، تعديل الاسم، الإضافة، أو رفع صور المعاينة (لكن يستطيع **رؤية وفتح** أي صورة معاينة موجودة).
  - بالإضافة لمفهوم "المشرف الرئيسي" (Root) الذي وحده يمكنه إضافة/حذف مشرفين آخرين.
- **صورة معاينة لكل ملف**: المشرف يرفق صورة (PNG/JPG/WEBP) مع كل ملف تصميم، يراها جميع المستخدمين (مشرفين ومشغّلين) كصورة مصغّرة في الجدول، وبالضغط عليها تُفتح في نافذة معاينة بالحجم الكامل.
- **حالة الاتصال (Online/Offline) في صفحة المستخدمين** — برؤية هرمية:
  - المشرف الرئيسي يرى حالة اتصال الجميع.
  - المشرف العادي يرى حالة (المشرفين العاديين + المشغّلين) فقط — لا يرى حالة المشرف الرئيسي.
  - المشغّل (إن أُتيح له الوصول لصفحة المستخدمين مستقبلاً) يرى حالة المشغّلين الآخرين فقط — لا يرى حالة أي مشرف.
- **ماكينتان ثابتتان**: كبيرة وصغيرة، كل واحدة لها حالة (تشغيل/إيقاف)، وقائمة ملفات (انتظار/جاري العمل/تم القص/تم التسليم).
- **رفع ملفات حقيقي** (DXF, SVG, AI, DWG, PDF, صور) يُخزَّن بشكل **دائم لا يُحذف أبداً** عبر Cloudflare R2 (راجع القسم التالي)، وتحميله من أي مستخدم.
- **سحب وإفلات** لإعادة ترتيب قائمة الملفات.
- **تحديث لحظي (Real-time)** عبر Socket.io: أي تغيير من أي مستخدم يظهر فوراً عند جميع المتصلين بدون تحديث الصفحة.
- **سجل عمليات (Logs)**: المشرف الرئيسي يرى كل العمليات، وكل مستخدم آخر يرى عملياته فقط.
- **إشعارات** لحظية عند إضافة ملف أو تغيير حالة ماكينة.

**بيانات الدخول الافتراضية (المشرف الرئيسي):**
- اسم المستخدم: `lol`
- كلمة المرور: `214205`
- **يُنصح بشدة بتغييرها بعد أول دخول** (عبر تعديل قاعدة البيانات مباشرة أو إضافة صفحة "تغيير كلمة المرور" لاحقاً).

## 3. تخزين الملفات الدائم (لا حذف أبداً) — Cloudflare R2

**المشكلة:** الاستضافات المجانية لتشغيل السيرفر (مثل Render) تحذف أي ملفات مرفوعة على القرص المحلي كل مرة يُعاد تشغيل السيرفر (وهذا يحدث تلقائياً بعد فترة خمول). هذه حقيقة مؤكدة من توثيق Render الرسمي، ولا علاقة لها بهذا الكود.

**الحل المُطبَّق في هذا المشروع:** الملفات المرفوعة (DXF/AI/DWG/...) تُخزَّن في **Cloudflare R2** بدل القرص المحلي. خصائصه:
- **10 جيجابايت تخزين مجاناً للأبد** (لا تنتهي بعد شهر أو سنة، بعكس أغلب الخدمات الأخرى)
- **بدون أي رسوم تحميل (egress)** حتى لو حمّل المستخدمون الملفات آلاف المرات
- الملفات **لا تُحذف عند إعادة تشغيل السيرفر إطلاقاً** — لأنها لم تعد على قرص السيرفر من الأساس

10 جيجابايت كافية لعشرات آلاف ملفات DXF/DWG/AI العادية (هذه الملفات صغيرة الحجم عموماً).

### خطوات الحصول على بيانات R2 (مجاني، 5 دقائق)

1. أنشئ حساباً مجانياً على [dash.cloudflare.com](https://dash.cloudflare.com) (بريد إلكتروني فقط، لا حاجة لبطاقة ائتمان للتسجيل الأساسي).
2. من القائمة الجانبية، اختر **R2 Object Storage**.
3. اضغط **Create bucket**، واختر اسماً (مثلاً `laser-cnc-files`) — احتفظ بهذا الاسم.
4. من نفس صفحة R2، اضغط **Manage API Tokens** → **Create API Token**.
5. اختر صلاحية **Object Read & Write**، وحدد البucket الذي أنشأته، ثم أنشئ التوكن.
6. ستظهر لك 3 قيم — احتفظ بها فوراً (لن تظهر مرة أخرى):
   - **Access Key ID**
   - **Secret Access Key**
   - **Account ID** (يظهر أيضاً في الشريط الجانبي لحسابك في Cloudflare، أو في رابط لوحة R2)

### ربطها بالمشروع

في ملف `.env` بالباك إند (محلياً) أو في متغيرات البيئة على الاستضافة (Render)، أضف:

```
R2_ACCOUNT_ID=الـ Account ID الذي حصلت عليه
R2_ACCESS_KEY_ID=الـ Access Key ID
R2_SECRET_ACCESS_KEY=الـ Secret Access Key
R2_BUCKET_NAME=laser-cnc-files
```

> **ملاحظة مهمة:** إذا تركت هذه المتغيرات فارغة، يعمل النظام تلقائياً بالتخزين على القرص المحلي (مناسب فقط للتجربة على جهازك؛ الملفات ستُحذف عند النشر على استضافة مجانية تعيد تشغيل السيرفر). لذلك **يجب تعبئة هذه المتغيرات قبل النشر النهائي**.

## 4. التشغيل محلياً (قبل النشر، للتجربة على جهازك)

### المتطلبات
- Node.js 16 أو أحدث
- MySQL 5.7+ أو MariaDB 10+

### خطوات التشغيل

```bash
# 1) إنشاء قاعدة البيانات
mysql -u root -p -e "CREATE DATABASE laser_cnc_system CHARACTER SET utf8mb4;"
mysql -u root -p laser_cnc_system < database.sql

# 2) تجهيز الباك إند
cd backend
cp .env.example .env
# عدّل ملف .env: ضع بيانات اتصال قاعدة بياناتك الحقيقية
npm install
npm run seed     # يضبط كلمة مرور المشرف الرئيسي بشكل آمن (bcrypt)
npm start         # يشغل السيرفر على المنفذ 5000 (أو كما حددت في .env)

# 3) تشغيل الفرونت إند (في نافذة طرفية أخرى)
cd ../frontend
python3 -m http.server 8080
# أو أي سيرفر ملفات ثابتة آخر تفضّله
```

افتح المتصفح على `http://localhost:8080` — تأكد أن `frontend/config.js` يحتوي على:
```js
window.APP_CONFIG = { API_BASE: "http://localhost:5000" };
```

> ملاحظة: إذا تركت متغيرات `R2_*` فارغة في `.env` (الوضع الافتراضي)، يخزّن النظام الملفات المرفوعة محلياً في مجلد `backend/uploads/` — وهذا مناسب تماماً للتجربة على جهازك. راجع القسم 3 أعلاه لتفعيل التخزين الدائم عبر Cloudflare R2 قبل النشر الفعلي.

> **لديك قاعدة بيانات منشورة مسبقاً (نشرت النظام قبل هذا التحديث)؟** لا تُعد تشغيل `database.sql` (سيحذف بياناتك الحالية). بدلاً من ذلك شغّل ملف الترقية فقط، الذي يضيف العمود الجديد دون لمس أي بيانات موجودة:
> ```bash
> mysql -u root -p اسم_قاعدة_بياناتك < migration_thumbnail.sql
> ```
> ثم أعد رفع ملفات `backend` و `frontend` المحدّثة فقط (بدون التعرض لقاعدة البيانات مرة أخرى).

## 5. النشر على استضافة مجانية

نظراً لأن المشروع يحتاج **Node.js + MySQL + تخزين ملفات دائم**، لا يمكن استخدام استضافة "static" بسيطة (مثل GitHub Pages) للباك إند. الحل الموصى به (مجاني تماماً):

| الجزء | الخدمة المقترحة | السبب |
|---|---|---|
| **Backend (Node.js)** | [Render.com](https://render.com) (الخطة المجانية) | يدعم Node.js + WebSocket (Socket.io) مجاناً |
| **قاعدة البيانات MySQL** | [FreeSQLDatabase.com](https://www.freesqldatabase.com) أو [db4free.net](https://www.db4free.net) | قواعد MySQL مجانية فعلية بدون بطاقة ائتمان |
| **Frontend (HTML)** | [Render Static Site](https://render.com) أو [Netlify](https://netlify.com) أو [GitHub Pages](https://pages.github.com) | استضافة ملفات ثابتة مجانية |

> ملاحظة: خدمات الاستضافة المجانية وشروطها تتغيّر بمرور الوقت. إن لم تعمل إحداها، ابحث عن "free Node.js hosting" أو "free MySQL hosting" للحصول على بديل مكافئ — الخطوات أدناه تنطبق على أي خدمة مشابهة بنفس المبدأ.

### الخطوة 1: رفع المشروع على GitHub

1. أنشئ حساباً على [github.com](https://github.com) إذا لم يكن لديك.
2. أنشئ مستودع (Repository) جديد، مثلاً باسم `laser-cnc-system`.
3. ارفع محتوى مجلد `laser-system` بالكامل (يمكنك رفعه بالسحب والإفلات من واجهة GitHub مباشرة في صفحة المستودع، أو باستخدام Git من جهازك).

### الخطوة 2: إنشاء قاعدة بيانات MySQL مجانية

1. اذهب إلى [freesqldatabase.com](https://www.freesqldatabase.com) واضغط "Create Database".
2. سجّل بإيميلك، وستحصل على بيانات اتصال مثل:
   - Host: `sqlXXX.freesqldatabase.com`
   - Database: `sqlXXX`
   - Username: `sqlXXX`
   - Password: `xxxxx`
3. باستخدام أداة مثل [phpMyAdmin](https://www.freesqldatabase.com) المرفقة مع الخدمة (أو أي عميل MySQL كـ HeidiSQL أو DBeaver)، افتح تبويب "Import" وارفع ملف `database.sql` لإنشاء كل الجداول والبيانات الأولية دفعة واحدة.
4. احتفظ ببيانات الاتصال (Host, Database, Username, Password) — ستحتاجها في الخطوة التالية.

### الخطوة 3: نشر الباك إند على Render

1. اذهب إلى [render.com](https://render.com) وسجّل دخول (يمكن الدخول مباشرة بحساب GitHub).
2. اضغط **New +** → **Web Service**.
3. اختر مستودع GitHub الذي رفعت المشروع عليه.
4. في إعدادات الخدمة:
   - **Root Directory**: `backend`
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: Free
5. في تبويب **Environment**، أضف متغيرات البيئة التالية (من ملف `.env.example`):

   | المتغير | القيمة |
   |---|---|
   | `DB_HOST` | Host الذي حصلت عليه من freesqldatabase |
   | `DB_PORT` | `3306` |
   | `DB_USER` | اسم المستخدم من freesqldatabase |
   | `DB_PASSWORD` | كلمة المرور من freesqldatabase |
   | `DB_NAME` | اسم قاعدة البيانات من freesqldatabase |
   | `PORT` | `5000` (أو اتركه، Render يحدد المنفذ تلقائياً عادة) |
   | `JWT_SECRET` | اكتب نصاً عشوائياً طويلاً وسرياً (مثلاً 40 حرف عشوائي) |
   | `JWT_EXPIRES_IN` | `7d` |
   | `ADMIN_CODE` | `4001` (أو غيّره لكود سري تختاره) |
   | `CLIENT_ORIGIN` | رابط الفرونت إند بعد نشره (مؤقتاً اتركه `*`) |
   | `MAX_FILE_SIZE_MB` | `20` |
   | `R2_ACCOUNT_ID` | من حساب Cloudflare R2 (راجع القسم 3 أعلاه) |
   | `R2_ACCESS_KEY_ID` | من حساب Cloudflare R2 |
   | `R2_SECRET_ACCESS_KEY` | من حساب Cloudflare R2 |
   | `R2_BUCKET_NAME` | اسم الـ bucket الذي أنشأته (مثلاً `laser-cnc-files`) |

   **مهم:** متغيرات `R2_*` هي ما يضمن عدم حذف الملفات المرفوعة عند إعادة تشغيل Render. بدونها يعمل النظام، لكن الملفات الفعلية (لا قاعدة البيانات) ستُحذف عند كل إعادة تشغيل.

6. اضغط **Create Web Service**. سيبدأ البناء والتشغيل تلقائياً (يأخذ دقيقة أو دقيقتين).
7. بعد الانتهاء، ستحصل على رابط مثل: `https://laser-cnc-backend.onrender.com` — هذا هو رابط الباك إند.
8. **مهم**: افتح "Shell" من لوحة تحكم Render لهذه الخدمة، وشغّل مرة واحدة:
   ```
   npm run seed
   ```
   هذا يضبط كلمة مرور المشرف الرئيسي (`lol` / `214205`) بشكل مشفّر بأمان في قاعدة بياناتك الحقيقية.
9. تحقق من سجل التشغيل (Logs) في Render — يجب أن تظهر رسالة `✓ تخزين الملفات: Cloudflare R2 (دائم)`. إذا ظهرت رسالة "القرص المحلي" بدلاً منها، فهذا يعني أن متغيرات `R2_*` لم تُضبط بشكل صحيح.

### الخطوة 4: نشر الفرونت إند

**الخيار الأسهل: Render Static Site**
1. من لوحة Render، اضغط **New +** → **Static Site**.
2. اختر نفس مستودع GitHub.
3. **Root Directory**: `frontend`
4. **Build Command**: اتركه فارغاً
5. **Publish Directory**: `.`
6. اضغط **Create Static Site** — ستحصل على رابط مثل: `https://laser-cnc-frontend.onrender.com`

### الخطوة 5: ربط الفرونت إند بالباك إند

1. عدّل ملف `frontend/config.js` في مستودع GitHub (يمكن التعديل مباشرة من واجهة GitHub: افتح الملف، اضغط على أيقونة القلم للتعديل):
   ```js
   window.APP_CONFIG = {
     API_BASE: "https://laser-cnc-backend.onrender.com"
   };
   ```
   (استخدم رابط الباك إند الحقيقي الذي حصلت عليه من الخطوة 3).
2. احفظ التعديل (Commit) — سيعيد Render نشر الفرونت إند تلقائياً بالرابط الجديد.
3. رجوعاً لإعدادات الباك إند في Render (Environment)، عدّل `CLIENT_ORIGIN` إلى رابط الفرونت إند الحقيقي (مثلاً `https://laser-cnc-frontend.onrender.com`) بدل `*`، لزيادة الأمان، ثم أعد نشر الخدمة (Manual Deploy).

### الخطوة 6: التجربة

افتح رابط الفرونت إند في المتصفح، سجّل دخول بـ `lol` / `214205`، وابدأ الاستخدام.

> ⚠️ ملاحظة عن الخطة المجانية في Render: الباك إند "ينام" تلقائياً بعد 15 دقيقة من عدم الاستخدام، ويستغرق حوالي 30-50 ثانية لإعادة التشغيل عند أول طلب جديد. هذا طبيعي في الخطط المجانية، وللحصول على سيرفر يعمل بدون توقف يلزم خطة مدفوعة (تبدأ من حوالي 7$/شهر).

## 6. الأمان قبل الاستخدام الفعلي في الشركة

قبل تشغيل النظام بشكل دائم لإدارة إنتاج حقيقي، تأكد من:

- [ ] تغيير `JWT_SECRET` إلى نص عشوائي طويل وسري (وليس القيمة الافتراضية في `.env.example`)
- [ ] تغيير كلمة مرور المشرف الرئيسي بعد أول دخول
- [ ] تغيير `ADMIN_CODE` (كود إضافة المستخدمين) إلى كود سري خاص بك
- [ ] ضبط `CLIENT_ORIGIN` على رابط موقعك الحقيقي فقط (لا تتركه `*` في الإنتاج)
- [ ] أخذ نسخة احتياطية دورية من قاعدة البيانات

## 7. هيكل قاعدة البيانات (ملخص)

| الجدول | الوصف |
|---|---|
| `users` | المستخدمون (مشرف/مشغل)، كلمات المرور مشفّرة بـ bcrypt |
| `machines` | الماكينتان الثابتتان (كبيرة/صغيرة) وحالتهما |
| `machine_files` | قائمة ملفات كل ماكينة (الاسم، الحالة، الوقت، الملف المرفوع فعلياً، صورة المعاينة) |
| `logs` | سجل كل العمليات في النظام |
| `notifications` | الإشعارات اللحظية |

راجع ملف `database.sql` للتفاصيل الكاملة لكل عمود.

## 8. الدعم الفني / التوسعات المستقبلية الممكنة

- صفحة "تغيير كلمة المرور" للمستخدم الحالي.
- تنبيهات عبر البريد الإلكتروني أو واتساب عند انتهاء ملف معيّن.
- لوحة تقارير وإحصائيات (عدد الملفات المُنجزة يومياً/أسبوعياً لكل ماكينة).
- مراقبة استهلاك مساحة Cloudflare R2 (10GB مجاناً، تنبيه عند الاقتراب من الحد).
